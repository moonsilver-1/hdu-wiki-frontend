**原子笔记（Atomic Notes）** 是 Zettelkasten 方法的核心原则：每张笔记只承载**一个独立的想法**。

## 为什么要"原子"？

想象你的知识库是一堆乐高积木：

* **大块笔记** = 一整块预制板 → 只能用在特定位置，无法灵活组合
* **原子笔记** = 标准乐高块 → 可以自由拼接成任何形状

原子笔记的优势：

| 大块笔记        | 原子笔记      |
| ----------- | --------- |
| 难以链接到其他笔记   | 精确链接到相关概念 |
| 搜索后需要翻找段落   | 搜到即是答案    |
| 写新文章要拆分旧笔记  | 直接组合现有卡片  |
| 容易成为"收藏但不看" | 每张都有明确用途  |

## 一张好的原子笔记长什么样

### 结构模板

```markdown
---
tags: [主题1, 主题2]
created: 2026-04-03
source: "来源"
---

## 断言式标题（核心观点就是标题）

正文：用 2-5 句话阐述这个想法。
用自己的话，不是照抄。
如果需要引用，标注来源。

---

相关：
- [[链接1]] — 为什么相关的一句话说明
- [[链接2]] — 补充/对比/支撑关系
```

### 关键要素

1. **断言式标题** — 标题本身就是一个观点
   * ❌ "关于费曼学习法"
   * ✅ "教别人是最有效的学习方式"

2. **正文简洁** — 2-5 句话说清楚，不要写成文章

3. **来源追溯** — 从哪里来的这个想法

4. **链接** — 至少链接 1 条相关笔记

## 粒度控制

### 怎么判断一张笔记是否"原子"？

问自己三个问题：

1. **能用一句话概括标题吗？** 如果需要"and"连接两个概念，应该拆分
2. **链接到其他笔记时，是指向整张还是某个段落？** 如果链接后需要说"参见第三段"，说明那张笔记不够原子
3. **在不同的文章/项目中能单独引用吗？** 如果总是和另一张笔记一起出现，考虑它们是不是应该合并

### 太大了？拆！

一张笔记包含多个观点 → 拆成多张，用链接连接。

```
❌ "费曼学习法的四个步骤和应用场景"

✅ 拆分为：
- [[教别人是最有效的学习方式]]
- [[费曼学习法的四个步骤]]
- [[简化解释能暴露知识盲区]]
- [[费曼学习法在编程中的应用]]
```

### 太小了？合！

如果一张笔记只有一句话且无法独立存在 → 合并到相关笔记中。

```
❌ "HTTP 状态码 404 表示未找到" — 这是事实，不是观点

✅ "HTTP 状态码的设计体现了 RESTful 的自描述原则" — 这是你的理解
```

## 从笔记到输出

原子笔记的终极价值在于**组合输出**：

```
写一篇文章 → 浏览相关笔记 → 挑选卡片 → 排列顺序 → 补充连接词 → 成文
```

这就是为什么卢曼说"我从不逼自己做不想做的事情。当我不知道该怎么继续时，我就做别的事情。"因为他的卡片盒里已经有大量可组合的想法，写作变成了**编排**而不是**创造**。
