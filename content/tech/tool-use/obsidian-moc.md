**MOC（Map of Content，内容地图）** 是 Nick Milo 在 LYT（Linking Your Thinking）框架中提出的概念。当你的笔记多到找不到时，MOC 就是你的导航页。

## MOC 是什么？

MOC 本身就是一张普通笔记，但它的内容是**其他笔记的链接集合**，按照某种逻辑组织。

把它想象成：

* 图书馆的**目录卡** — 指向具体的书，但本身不是书
* 城市的**地图** — 帮你找到目的地，但本身不是城市
* 网站的**导航页** — 链接到各个子页面

### MOC vs 文件夹

| 文件夹          | MOC             |
| ------------ | --------------- |
| 一个笔记只能在一个文件夹 | 一个笔记可以出现在多个 MOC |
| 刚性层级结构       | 灵活的网状结构         |
| 分类必须预先设定     | 随时可以新建和重组       |
| 无法表达关系       | 可以用描述文字解释链接关系   |

## 什么时候创建 MOC？

Nick Milo 的经验法则：

> 当你对某个主题有了 **5-10 条相关笔记**，开始感觉"有点乱了"，就该创建 MOC。

不要太早创建 — 2 条笔记不需要 MOC。
不要太晚创建 — 50 条笔记再整理太痛苦。

## MOC 的写法

### 基础版：链接列表

```markdown
## 认知科学 MOC

## 决策与思维
- [[系统1和系统2的切换成本]]
- [[减少决策数量比提升决策质量更有效]]
- [[锚定效应在产品定价中的应用]]

## 学习与记忆
- [[间隔重复的科学原理]]
- [[教别人是最有效的学习方式]]
- [[遗忘曲线与最佳复习时间点]]

## 习惯与行为
- [[习惯的复利效应]]
- [[环境设计比意志力更可靠]]
```

### 进阶版：带叙事的 MOC

```markdown
## 个人生产力 MOC

生产力不是做更多的事，而是做**对的事**。

最核心的原则是 [[减少决策数量比提升决策质量更有效]]。
在此基础上，[[GTD 中的下一步行动]] 提供了具体的执行框架，
而 [[时间块方法]] 解决了"什么时候做"的问题。

对于知识工作者，[[深度工作]] 是产出的关键。
要实现深度工作，需要 [[环境设计比意志力更可靠]] 和
[[习惯自动化]] 来减少干扰。

当多个项目并行时，[[PARA 组织法]] 可以帮助区分
"该做的"和"可以做的"。
```

带叙事的 MOC 更有价值——它不只是索引，本身就是一次**思考的结晶**。

## MOC 的 MOC

当你有了很多 MOC，可以创建一个更高层级的总索引：

```markdown
## 🏠 Home

## 我在研究的
- [[认知科学 MOC]]
- [[软件工程 MOC]]
- [[个人生产力 MOC]]

## 我在做的项目
- [[项目A MOC]]
- [[项目B MOC]]

## 持续关注的
- [[AI 发展 MOC]]
- [[阅读清单 MOC]]
```

这个 Home 页面就是你整个知识库的入口。

## 动态 MOC（配合 Dataview）

用 Dataview 插件自动聚合，笔记增加时 MOC 自动更新：

````markdown
## Python 学习 MOC

以下笔记自动聚合：

```dataview
LIST
FROM #python
SORT file.ctime DESC
```
````

## 最佳实践

1. **MOC 不是文件夹** — 同一条笔记可以被多个 MOC 引用
2. **保持精炼** — 一个 MOC 不超过 30-50 条链接，太多了就拆分
3. **定期维护** — 每月浏览一次，更新过时的链接
4. **先积累后组织** — 笔记先写，MOC 后建
