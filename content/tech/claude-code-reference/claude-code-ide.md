hihi！洛洛又来了！

这篇算是本目录里最轻松的一篇，没有代码，没有参数，就是帮你选个入口。

起因是洛洛之前一直有个误解：以为 Claude Code 就是那个黑框框，只能在黑框框里用。后来发现它在 VS Code 里有、桌面上有、手机上还有，我人都懵了——那我到底该用哪个？是不是手机版比较弱？

答案是：都是同一个它，只是你从哪扇门进去的区别。

Claude Code 现在不是单一 CLI 工具，而是一组入口。不同入口共享 Claude Code 的 agent 能力，但适合的工作场景不同。

## CLI

先说洛洛自己天天用的这个，也是最没有惊喜、最靠得住的那个。

CLI 仍然是最稳定、最透明的入口：

```bash
claude
```

适合：

* 日常开发
* 大规模重构
* 本地测试和构建
* 需要精细控制权限、Hooks、MCP 的任务

如果你不确定从哪里开始，优先用 CLI。

"最透明"这个词洛洛体会很深。黑框框虽然丑，但它干了什么全写在屏幕上，一行都不藏。别的入口好看，但有时候你会不知道它背后到底跑了啥。

洛洛注意到默子老师从来不用那些花里胡哨的入口，永远是终端。问他为什么，他说"看得清"。三个字，我记住了。

## VS Code

如果你受不了纯文字，那就用这个。

VS Code 适合边看代码边和 Claude 协作：

* 在编辑器里查看 diff
* 直接打开相关文件
* 结合终端运行测试
* 使用项目里的 `.claude/` 配置

安装方式以 VS Code Marketplace 当前显示为准。装完后，建议先确认扩展调用的是你期望的本机 `claude`，避免系统里存在多个安装来源。

## JetBrains

写 Java、Kotlin 的朋友，这块洛洛完全没资格发言，原样给你：

JetBrains 适合 Java、Kotlin、后端和大型工程：

* 可以用插件入口
* 也可以直接在 IDE 内置终端运行 `claude`
* 项目权限和 MCP 配置仍然按当前工作目录生效

插件版本、支持的 IDE 和功能会随官方发布变化，安装前看当前 Marketplace 页面。

那条"也可以直接在 IDE 内置终端运行 `claude`"洛洛觉得很实用。插件万一没跟上版本，还有终端这条退路，等于永远不会被卡死。

## Desktop

这个是洛洛第二喜欢的入口，因为它长得好看。

Desktop 适合管理多个本地会话：

* 多项目并行
* 可视化查看会话
* 结合 worktree 做隔离
* 拖拽文件或图片作为上下文

它更像本地 Claude Code 会话管理器，不是替代项目里的 CLI 配置。

"拖拽文件或图片作为上下文"！设计选手狂喜。洛洛经常需要把设计稿丢给它看，能直接拖进去这件事真的美丽之。

## Web 与 Mobile

来了，手机上的那个。

Web 和移动端适合：

* 临时查看任务状态
* 审批或跟进长时间任务
* 在离开电脑时继续处理轻量工作

涉及本地仓库、私有依赖、复杂构建和本机工具链时，还是优先用本地 CLI 或 IDE。

洛洛的用法是"查看用"。躺床上刷一眼跑到哪一步了，很爽；真要动手改东西还是得起来开电脑。这个分工洛洛觉得挺健康的，不然真的会在被窝里改代码改到天亮。

## Remote Control

这个名字听起来最玄，其实是前两种的结合。

Remote Control 是混合模式：

* Claude Code 在本机运行
* 通过远端界面查看进度、发送消息、处理审批
* 本机仍然负责文件系统、命令执行和项目工具链

适合长任务监控，但不应该绕过本机权限、沙盒和 Git 审查。

也就是干活的还是你那台电脑，你只是拿着遥控器。洛洛脑补的画面是电脑在宿舍加班，人在食堂吃饭顺手点两下"同意"。

## 选择建议

懒得看上面那一堆的，直接查这张表：

| 场景                 | 推荐入口                          |
| ------------------ | ----------------------------- |
| 本地开发、复杂改造          | CLI                           |
| 前端、全栈、边写边看 diff    | VS Code                       |
| Java/Kotlin、大型后端工程 | JetBrains                     |
| 多项目、多会话管理          | Desktop                       |
| 外出时跟进任务            | Web / Mobile / Remote Control |
| CI、脚本、批处理          | Headless                      |

不要把某个入口当成能力边界。真正决定 Claude Code 行为的是当前项目、权限模式、`settings.json`、Hooks、MCP 和你给它的任务范围。

## 洛洛的总结

最后那段话，洛洛想抄在本子上。

它的意思是：手机版不是"弱化版"，桌面版也不是"高级版"。它们背后都是同一套规则——你的项目、你的权限设置、你给它的任务边界。换入口不会让它变强，也不会让它变笨。

所以别纠结了，挑一个你最愿意打开的。洛洛的组合是：白天 CLI，晚上躺着用手机看它跑完了没有。

想给它接更多外部能力，去看[MCP](/tech/claude-code-reference/claude-code-mcp)；想收一波零碎的小技巧，去看[实用技巧](/tech/claude-code-advanced/claude-code-tips)。
