洛洛先讲一个惨案。

洛洛当时对着一个完全不熟的项目说了一句"帮我改一下登录逻辑"，然后就去泡泡面了。回来一看，它改了十一个文件。

十一个。洛洛一个都看不懂。撤回也不敢撤，因为不知道哪些是对的。最后厚着脸皮去找默子老师，他看了一眼说："你为什么不先让它把计划写出来。"

……可以先写计划的吗！！！

可以的。这个功能叫 Plan 模式，洛洛现在做任何超过三个文件的事情之前都会先开它。

Plan 模式让 Claude 在动手之前先深度思考和规划，只读分析代码库，输出可审查的执行计划。

## 什么时候用 Plan 模式？

洛洛的经验是：只要你心里有一点"它会不会乱改啊"的不安，就开。

* **不熟悉的代码库** — 先让 Claude 调研理解，再决定怎么改
* **大规模重构** — 涉及多个文件的变更，需要先理清依赖关系
* **复杂功能开发** — 需要考虑架构设计、接口兼容性
* **跨团队评审** — 生成计划文档给团队其他成员审查

第一条就是洛洛的泡泡面惨案。第四条洛洛也用过一次，把计划直接甩给同学看，比洛洛自己解释清楚多了，毕竟洛洛也没完全看懂。

## 如何进入 Plan 模式

### 快捷键切换

按 `Shift+Tab` 在模式之间循环：

```text
default / acceptEdits / plan 等常用模式
```

具体顺序以当前版本的终端状态栏为准。看到 Plan Mode 后停下即可。

洛洛一开始按太快了，一路按过去又绕回来，还以为自己电脑坏了。慢一点按，眼睛盯着状态栏那行字，看到 Plan Mode 就松手。

### 启动时指定

```bash
claude --permission-mode plan
```

一开始就知道这次要规划的，直接这么起，省得再按。

## Plan 模式的行为

那"只读"到底只读到什么程度？这张表说得很清楚，洛洛看完就安心了。

在 Plan 模式下，Claude：

| 能做              | 不能做          |
| --------------- | ------------ |
| 读取文件（Read）      | 编辑文件（Edit）   |
| 搜索代码（Grep、Glob） | 写入文件（Write）  |
| 理解项目结构          | 执行会修改项目状态的命令 |
| 输出分析和计划         | 创建/删除文件      |

右边那一整列，全是洛洛半夜会心慌的操作，在这个模式下它一个都干不了。安全之。

> **洛洛碎碎念**
>
> Plan 模式最爽的不是"更聪明"，是**你能在它动手之前把它拦下来**。
> 
>   洛洛零基础，看不懂代码，但洛洛看得懂中文计划书啊！计划里写"删除 session 相关依赖"，洛洛就能问一句"删了会不会影响别的地方"。
> 
>   这大概是洛洛这种非技术选手唯一能对项目负责的方式了，好好珍惜之。

## 典型工作流

下面这五步是洛洛现在每次都走的固定套路。

### 第一步：进入 Plan 模式，描述任务

```
帮我重构用户认证模块，从 session-based 改为 JWT
```

### 第二步：Claude 深度分析

Claude 会：

1. 搜索所有认证相关的文件
2. 阅读关键代码（路由、中间件、模型）
3. 理解现有的认证流程
4. 识别所有需要修改的文件

这一步要等一会儿，屏幕上会刷一大堆东西。洛洛第一次以为它卡住了，其实它在翻你整个项目。这个时候适合去泡泡面，但这次泡完回来是有计划书的，不是十一个被改过的文件。

### 第三步：Claude 输出计划

```markdown
## 重构计划

### 需要修改的文件
1. src/middleware/auth.ts — 替换 session 验证为 JWT 验证
2. src/routes/login.ts — 登录成功后返回 JWT token
3. src/routes/register.ts — 注册后同时返回 token
4. src/lib/jwt.ts — 新建，JWT 工具函数
5. src/types/auth.ts — 更新类型定义

### 执行顺序
1. 先创建 JWT 工具库
2. 修改登录/注册路由
3. 替换认证中间件
4. 更新所有受保护路由的类型
5. 删除 session 相关依赖

### 注意事项
- 需要安装 jsonwebtoken 包
- 前端需要同步修改 token 存储方式
- 现有登录用户需要重新登录
```

天哪，这个「注意事项」才是精华。"现有登录用户需要重新登录"——这种事情如果不是它提前写出来，洛洛是绝对想不到的，等到用户来投诉才发现就晚了。

### 第四步：审查和调整

你可以对计划提出修改意见：

```
还需要考虑 refresh token 机制，以及 token 过期后的自动续签
```

Claude 会更新计划。

计划不满意就直说，这一步是免费的。洛洛经常来回改三四轮，反正在这个模式下它一个字的代码都还没动。

### 第五步：切换回普通模式执行

按 `Shift+Tab` 切换回 `default`、`acceptEdits` 或其他可执行模式：

```
按照刚才的计划开始执行
```

Claude 会按照计划逐步修改代码。

## Plan 模式 + Subagent

Plan 模式下，Claude 会使用 **Plan subagent**（继承当前模型）来进行深度研究。这个 subagent 可以并行搜索多个方向，汇总后提供全面的分析结果。

洛洛不懂 subagent 具体怎么实现的，但"并行搜索多个方向"这句话听起来就很牛逼。理解成它派了好几个小分队同时往不同方向找，找完回来一起汇报——大概是这个意思吧。

## 最佳实践

1. **先 Plan 后执行** — 对于复杂任务，永远先 Plan
2. **要求具体** — 不要只说"帮我重构"，要说清楚重构的目标和约束
3. **迭代计划** — 第一版计划不满意？继续对话调整
4. **保存计划** — 好的计划可以要求 Claude 写入文件，留作文档

> **洛洛碎碎念**
>
> 第二条就是洛洛的原罪。
> 
>   洛洛那句"帮我改一下登录逻辑"，现在回头看简直是在给它开无限授权。它当然只能自己猜，猜出十一个文件也不能全怪它。
> 
>   好吧，还是可以怪一下奶龙的，是它当时在旁边一直叫，洛洛才随手打了那么一句就跑去泡面。
