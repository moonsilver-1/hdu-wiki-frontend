洛洛通宵到凌晨四点那次，是真的被"忘事"这件事伤到了。

前面聊了三个小时，我们已经把整个页面结构、配色、命名规则全对齐了，配合默契得像老搭档。然后我说了一句"照刚才说的把第二个组件也改了"。

它问我：刚才说的是哪个？

我当场愣住。天哪！我们不是聊了一整晚吗！

后来才知道这不是它记性差，是空间真的满了。上下文窗口就那么大，装不下我的三个小时。

Claude Code 的上下文窗口是有限的，具体大小取决于当前模型和账号权限。长时间会话中，合理管理上下文是高效使用的关键。

## 上下文是什么？

先搞清楚这个"空间"到底被什么占了，后面的操作才会讲得通。

上下文 = 整个对话历史 + 工具调用结果 + 系统指令。每次你和 Claude 对话、每次 Claude 读取文件、执行命令，都会消耗上下文空间。

当上下文快满时，Claude Code 会提醒你，并可能自动压缩。

注意"每次 Claude 读取文件"这句。洛洛以前以为只有我打的字算数，其实它读的每一个文件、跑命令吐出来的每一行输出，全都堆在同一个空间里。我那一晚让它读了十几个文件，等于我自己把房间塞满了，然后怪它记性不好。菜之。

## /compact 命令

知道空间会满，第一个要学的就是怎么腾地方。

这是最重要的上下文管理工具。

```
/compact
```

**工作原理：**

1. 将当前完整对话发送给模型
2. 模型生成精炼摘要，保留关键信息
3. 用摘要替换冗长的原始对话
4. 释放大量 token 空间

souga，原来它是让模型自己给自己写会议纪要，然后把三小时的录音换成一页纸。洛洛听懂这个的时候真的拍桌了。

### 自定义压缩重点

```
/compact 重点保留关于数据库架构的讨论
```

```
/compact 只保留最近的代码修改和当前任务目标
```

带参数的 `/compact` 会引导压缩过程优先保留你关心的信息。

这个太实用了。写纪要的人不知道你在意什么，那你就直接告诉它在意什么——洛洛现在基本不裸用 `/compact`，都会带一句"重点保留配色和命名规则"。

## /clear 命令

有时候你不是想腾地方，是想彻底换个话题重新开始。

完全清空对话历史，从零开始：

```
/clear
```

适合在不相关的任务之间切换。比如你刚修完一个 bug，现在要开发新功能，用 `/clear` 清掉无关上下文。

> **洛洛碎碎念**
>
> `/clear` 和 `/compact` 千万别按错！！！
> 
>   `/compact` 是整理房间，`/clear` 是把房间搬空。
> 
>   洛洛手快按过一次 `/clear`，前面辛辛苦苦对齐的所有设定，一秒钟没了。当时那个空荡荡的界面看得我很想哭。
> 
>   怪奶龙，它那天在我脚边，我分心了。

## 减少上下文消耗的技巧

上面两个是"满了怎么救"，下面这五条是"怎么别那么快满"。洛洛觉得这一节才是真正省命的部分。

### 1. 精确读取文件

不要：

```
读一下 src/app/layout.tsx
```

更好：

```
读一下 src/app/layout.tsx 的第 10-30 行
```

Claude 的 Read 工具支持 `offset` 和 `limit` 参数，只读取需要的部分。

### 2. 用搜索代替全文读取

不要：

```
帮我找找哪里用了 getUserById 这个函数
```

（Claude 可能会挨个读文件）

更好：

```
搜索代码库中所有调用 getUserById 的地方
```

（Claude 会用 Grep 工具，高效且省上下文）

这两条其实是同一个道理：**别让它把整本书搬进房间，让它只带需要的那一页。** 洛洛当初那十几个文件，八成只用得上其中几十行。

### 3. 及时使用 /compact

不要等到上下文快满了才压缩。完成一个阶段性任务后，主动 `/compact` 一下。

洛洛这种拖延症选手最容易犯这条。等到它开始忘事再压缩，那已经是抢救了。

### 4. 拆分大任务

与其在一个超长会话中完成所有事情，不如拆成几个独立会话。每个会话聚焦一个子任务。

### 5. 利用 /btw 做快速提问

```
/btw TypeScript 的 satisfies 关键字怎么用？
```

`/btw` 的内容不会进入主对话历史，适合做快速提问而不污染上下文。

这个洛洛用得贼多，因为洛洛属于随时会冒出一个"欸这个是什么意思"的类型。以前我直接在主对话里问，问完发现房间又被我的好奇心占掉一块。现在一律走 `/btw`，问完当没发生过。美丽之。

## 上下文指示器

好消息是你不用凭感觉猜还剩多少。

Claude Code 界面会显示当前上下文使用情况，输入 `/context` 还能看到详细占用。下面的百分比是经验值，不是官方阈值：

* **正常**：上下文使用 \< 60%，可以继续工作
* **注意**：上下文使用 60-80%，考虑 `/compact`
* **紧张**：上下文使用 > 80%，尽快 `/compact` 或 `/clear`
* **自动压缩**：Claude Code 在极限时会自动触发压缩

洛洛现在的习惯是每写完一段就瞄一眼那个数字，跟看手机电量一个感觉。默子老师说过一句话洛洛一直记着：到 80% 才动手，你已经在被动挨打了。

## /cost 查看消耗

```
/cost
```

显示用量和费用，帮你了解使用成本。截至 2026-09-14，`/cost` 已是 `/usage` 的别名。

## 收工

回头看那个凌晨四点的洛洛，其实问题不在它记性，在我根本不知道有这个空间存在。

现在洛洛的三个习惯：能搜就不通读，阶段完了就 `/compact`，随手的问题走 `/btw`。就这三下，聊一整晚也不会再出现"刚才说的是哪个"。
