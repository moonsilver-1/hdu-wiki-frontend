装好了之后，洛洛盯着那个光标闪了大概十分钟。

因为没人告诉我该打什么。我脑子里的印象是"跟电脑说话得用命令"，所以我很郑重地敲了一句 `run project`。它没懂。我又敲 `start`。还是没懂。

最后我泄气了，直接打了一句中文："这个项目是干嘛的？"

它读了一圈文件，然后一条一条讲给我听。

……原来它就是这么用的。菜之。

所以这篇讲的其实是一件很简单的事：**你想干什么，就直接说什么。** 下面是洛洛平时用得最多的几种说法。

## 启动

在项目目录下运行：

```bash
claude
```

进入交互模式后，直接用自然语言告诉它你要做什么。

注意是"在项目目录下"，这句别跳过。洛洛有一次在桌面上启动它，然后让它改我的代码，它当然找不到——它只认得你现在站在哪。

## 常见用法

下面这几类不是什么"标准指令格式"，就是人话。洛洛列出来只是给你打个样，让你知道嘴可以张多大。

### 写代码

```
帮我写一个用户登录的 API，用 Express + JWT
```

Claude 会自动创建文件、安装依赖、写测试。

对，测试也是它自己写的。洛洛第一次看到它写完代码还顺手补了测试，感觉像点了份外卖结果送来一整桌。

### 改 Bug

```
这个函数报错了 TypeError: Cannot read property 'map' of undefined，帮我修一下
```

它会读取相关代码，定位问题，直接修复。

**报错信息一定要原样粘进去！！！** 洛洛以前很爱概括，比如"它报了个错"，然后 Claude 就只能猜。把那一整串看不懂的英文整段复制过去，效果差得非常明显。

### 理解代码

```
解释一下 src/lib/auth.ts 这个文件在做什么
```

这个用法洛洛用得最多，因为洛洛看代码就是看天书。

### 重构

```
把 src/utils/ 下所有的 var 改成 const/let
```

### 执行命令

```
跑一下测试看看有没有挂的
```

Claude 会执行 `npm test` 并分析结果。

## 单次命令模式

上面都是"进去聊天"，但有时候你只想问一句就走，不想开一整场对话。

不进入交互模式，直接执行一个任务：

```bash
claude -p "解释一下这个项目的目录结构"
```

`-p` 参数传入提示词，执行完自动退出。

洛洛接手别人项目的时候几乎都是先来这一句，看完再决定要不要正式进去。

## 继续上次对话

昨晚聊到一半困死了去睡了，第二天想接着来——不用重新解释一遍：

```bash
claude --continue
```

或进入后输入 `/resume`，从历史会话里挑一个接着聊。

ddl 战士必备之。

## 多文件操作

最后说一个洛洛觉得最神的地方。

Claude 可以同时读写多个文件。比如：

```
帮我创建一个完整的 CRUD API，包括路由、控制器和数据库模型
```

它会一次性创建所有需要的文件。

洛洛当时是真的往后靠了一下，看着终端里一个个文件名往外冒。天哪！
