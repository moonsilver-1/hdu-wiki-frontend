## 不写归属条款，著作权默认归你

这条跟大多数客户的直觉相反，也是接单方在谈判里最被低估的筹码。

《著作权法》第十九条：

> 受委托创作的作品，著作权的归属由委托人和受托人通过合同约定。合同未作明确约定或者没有订立合同的，著作权属于受托人。

《计算机软件保护条例》第十一条：

> 接受他人委托开发的软件，其著作权的归属由委托人与受托人签订书面合同约定；无书面合同或者合同未作明确约定的，其著作权由受托人享有。

也就是说，你把东西交出去了，著作权还在你手上——除非合同里写了转让。

有个流传很广的补充说法要谨慎对待：「即使著作权归受托人，委托人也可以在委托创作的特定目的范围内免费使用」。这条出自 2002 年的著作权法司法解释，2020 年修正的《著作权法》正文里没有这个表述。实务上还是把使用范围写进合同，别依赖默认规则。

### 转让和许可的形式要求

第二十七条管转让：转让财产权应当订立书面合同，列明作品名称、转让的权利种类与地域范围、转让价金、支付日期与方式、违约责任。

第二十六条管许可：许可使用合同要包括许可的权利种类、专有还是非专有、地域范围与期间、付酬标准与办法、违约责任。

所谓「书面」，在电子合同和平台聊天确认的语境下不必须是纸质，但条款要素要齐。个人接单至少要写清四件事：给的是转让还是许可、许可是专有还是非专有、用途和地域和期限、价款与支付节点。

## 把权利做成三个价格档

价差通常在 1.3 到 3 倍之间，没有统一标准，看行业。

| 档位       | 内容                                                       |
| -------- | -------------------------------------------------------- |
| A 档（基础价） | 著作权归接单方；客户获得非独占、不可转授权的使用许可，用途限于约定用途，地域和期限按约定；接单方保留作品集展示权 |
| B 档（加价）  | 客户获得独占使用许可（接单方不得再许可他人，但著作权仍在接单方）；接单方保留署名与作品集展示权          |
| C 档（高价）  | 著作权的财产权部分转让给客户；可约定接单方保留署名权与有限的作品集展示权（署名权等人身权不可转让）        |

这是应对压价最健康的一条杠杆。客户嫌贵，你可以从 C 档降到 A 档——价格下来了，但你交付的工作量一点没少，只是保留了更多权利。比直接打折健康得多，因为它不否定你的初报价。

### 权利跟着尾款走

境外模板的通行写法是：

> All rights, title and intellectual property in the deliverables transfer to the Client only upon receipt of payment in full.

中文对应：

```
本项目交付物的相关权利自客户付清全部款项之日起转移或授权生效；
款项付清前，接单方保留全部权利。
```

这条配合《民法典》第七百八十三条（未付款可拒绝交付、享有留置权），构成尾款保护的双保险。

## 分批交付

| 类型      | 预览版（尾款前）          | 正式版（尾款后）                         |
| ------- | ----------------- | -------------------------------- |
| 设计 / 插画 | 加水印的 JPG、低分辨率     | 无水印高清 + 源文件（PSD / AI / Figma 权限） |
| PPT     | 导出 PDF 或图片版       | 可编辑 PPTX + 字体说明                  |
| 视频      | 带水印或时间码的低码率预览     | 无水印成片 + 工程文件（如约定）                |
| 软件      | 演示环境、测试账号，或打包应用   | 源码仓库权限 + 部署文档                    |
| 数据处理    | 样例结果（前 N 条）+ 统计摘要 | 完整结果 + 脚本                        |

拿捏的分寸是：预览版要足够让客户判断质量，但不足以直接拿去用。预览版本身也要在报价单里写明未付清款项前不得使用。

### 实际做的人怎么处理

**软件类：只给演示，不给包。** 论坛里被反复说的几个版本——「做完了给拍演示视频，或提供演示服务，拿到钱才给程序和代码，大不了我当练手」「定金 → 开发 → 视频演示不交付 → 满意就付款然后交付，不满意再改」「展示别给代码，远程操作别给代码，转账再给代码」。另有人的做法是给的测试包带接口，不给钱就无规律闪退。

**授权期是合法版本，后门不是。** 有人给过一条边界划得很清楚的建议：

> 做一个许可证功能，付尾款是永久许可，没付尾款是有限期许可。法律有规定不能设软件炸弹，要负刑责的，所以千万别藏着掖着，许可证要大大方方显示在启动界面或「关于系统」界面。上线给第一个许可证号大方些，直接半年或更长。

同一批讨论里也有人明确指出留后门、远程停服属于违法行为。**区别在于是否公开、是否事先约定**：写进合同、显示在界面上的授权期是正常商业安排；藏起来的定时炸弹是另一回事。别越过这条线。

**文档资料类：加密加预览。** 别直接卖 PDF。把文件压缩加密码，先给买家看前几页预览，提前说清「拍下、收货，就给密码，不接受就别拍」。或者把资料拆开，先给一部分，确认之后再给剩下的。

**图像类：水印是行业标配。** 插画圈有一条判断标准值得所有做视觉的人记住——**「要无水印大图」「要源文件」「要源码」这类要求发生在付款之前，本身就是骗稿信号。** 豆瓣小组里有插画师的原话是「我们辛辛苦苦花了几天画好的图，你们一分钱没支付，要我们发大图还不能加水印，您觉得合理吗」。

论坛里出现频次最高的一条铁律，就是这件事的总结：**一手交尾款，一手交源码。** 有人写「现在源码也给了」，尾款从十月拖到十二月，回复区一致认为已无解。

## 平台要求你留的凭证

《交易争议处理规范》第十一节是专门写服务类交易的，其中第一百零二条把举证责任明确给了卖家：

> 买卖双方通过线下完成服务成果交付的，卖方需对交付服务的凭证予以留存并妥善保管，否则由卖方承担交易不利后果。

用网盘、邮件、微信传文件交付的，留不下凭证就自己承担败诉后果。

同一节还有两条对卖家有利的。第九十九条给了服务类交易的定义；第一百条更实用：

> 服务订单交付时间届满前，卖方已产生实质服务行为的，或卖方依约已完成服务的，买方要求退款或拒绝接受服务的，需与卖方协商一致。

只要能证明「已产生实质服务行为」，买家就不能单方面要求退款。反过来说，过程记录本身就是你的资产。

具体该留的：交付链接的发送记录（时间、文件名）、网盘的分享日志、带日期版本号的版本文件、软件类的 commit 历史、以及客户确认收到的那条消息。

## 验收

用验收标准逐条对，不用「满意不满意」对。

必须有视为验收条款。境外 SOW 模板通行的是 10 个工作日，个人小单可以缩到 3 到 5 天：

```
乙方交付后 3 个工作日内，甲方未以书面形式（含平台聊天消息）
提出具体不符合验收标准的异议的，视为验收通过。
```

客户拿质量说事拒绝验收时，《民法典》第七百八十一条给的救济是：不符合质量要求的，定作人可以合理选择请求承揽人承担修理、重作、减少报酬、赔偿损失等违约责任。

修复优先，不是无条件退全款。这条在争执时很好用。

## 售后期限

写法：

```
自验收通过之日起 15 个自然日为免费售后期，
范围限于不符合《验收标准》的缺陷修复；
不含：新增功能、环境迁移、第三方平台规则变化导致的调整、
客户自行修改引发的问题。
超出部分按 X 元/小时或另行报价。
```

别写「交付后概不负责」。售后期之外法定的质量责任仍在，这种条款大概率无效。把「缺陷」的定义写清楚反而更能保护自己——范围界定得越具体，什么不属于免费售后就越清楚。

如果开通了「描述不符全额退」服务，还要留意规则里的响应时限：确认收货前的退款申请 72 小时内不响应就自动同意，确认收货后的服务申请 48 小时，买家可以在确认收货起 60 天内发起。

而该规则认定的「描述不符」明确包括服务内容与使用周期跟描述不符，以及承诺交付时间、可达到的效果跟描述不符。

换句话说，详情页写的每一句承诺都会被拿来对照。开通这项服务能提高转化，代价是把承诺变成了可追责事项。
